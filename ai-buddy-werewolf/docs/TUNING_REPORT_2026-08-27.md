# 討論・主人相談ターン調整レポート（2026-08-27）

## 結論

旧公開版で確認した最大の問題は、Live AIの能力そのものよりも、**主人が助言できる時点を保証しないまま討論が進み、質問や反論が完結しない進行構造**だった。候補版では討論を `opening → awaiting_master_advice → response` の3段階に分け、最初の議論後に必ず主人へ操作を返す。相談中は討論時計を止め、助言または明示的なスキップ後に残り時間で質問・回答・追加反応を続ける。

モック100試合ではQuick Testの市民/狼勝率が59%/41%となり、平均AIコール数と無根拠な疑い表明を大きく抑えた。公開後はSonnet 5 / effort lowでLiveを2試合実行し、**主人相談、個別質問、単独回答、追加追及、前日発言の矛盾追跡、確定情報の内部反映**まで確認した。旧基準比で調整後2試合の平均AIコール数は45.1%減、平均推定原価は45.2%減、平均延べAI処理時間は41.6%減となった。

現設定はPhase0の主検証設定として採用できる。ただし占い役の1試合では、共有された白情報をバディが内部では正しく使ったものの卓へ公表せず、白対象が処刑された。これは自律判断として仕様内だが、白対象が処刑目前でも役職を伏せ続ける比率は追加測定が必要である。1試合だけで公開判断を強制するプロンプトへ変えず、次の比較軸として記録する。

## 目指す体験

対人チャットの暴言、初心者排斥、専門用語の圧力をAIバディが引き受けつつ、心理戦・嘘・推論は薄めない「ギスギスしない本格人狼」を目標にする。そのため、単に発言数や主人との一致率を増やすのではなく、次を重視する。

- 初日でも裁判前に弁明・他者意見・主人助言・応答が一巡する
- 名指しや質問が投げっぱなしにならず、対象本人が答える
- 「名前を出された」「焦点対象になった」「黙っていた」だけを疑いの根拠にしない
- 侮辱や初心者排斥を避けながら、矛盾の追及、誘導、嘘、身内切りなどは許す
- 主人の確定情報は主人だけに届き、共有するかを主人が選ぶ
- 親密度が高いほど主人の意見を優先するが、最終行動はバディが決める

## 旧公開Live基準

旧公開設定でQuick Testを1試合、`anthropic/claude-sonnet-5` で実行した。2日で狼陣営が勝利した。

| 指標 | 実測 |
|---|---:|
| 日数 | 2日 |
| AIコール | 92 |
| 入力token | 446,197 |
| 出力token | 28,039 |
| 推定原価 | $1.1728 |
| 延べAI処理時間（並列分を含む） | 674.4秒 |
| エラー / リトライ / JSON失敗 / フォールバック | 1 / 2 / 3 / 1 |

推定原価は `config/models.json` の登録単価から算出した参考値で、OpenRouterの確定請求額ではない。旧公開版はEdgeで構造検証に失敗した試行や締切Abortのusageを回収できないため、$1.1728は過少計上の可能性もある。`674.4秒` は各コールのレイテンシーを合算した値で、並列分を含むため人間が実際に待った時間ではない。

質的には、定型文よりも名指し質問と応答が生まれ、Liveを使う価値は確認できた。一方で次の重大な問題があった。

1. AI処理中に主人の助言ボタンが無効のまま進み、試合中に助言できなかった。ゲームの核を検証できない
2. 2日目は「具体的根拠がない」という同じ論点が繰り返された
3. 評価ごとに長い公開発言履歴を再送し、入力tokenが446,197まで膨らんだ
4. 試合終了直後に `finishedAt` が確定せず、結果画面の総試合時間が欠損した

したがって、この1試合は会話品質の参考にはなるが、主人助言を含む完成したゲーム体験の基準試合とは扱えない。

## 候補版で変更したこと

### 1. 主人の番をルールとして保証

- `opening`: 初日の焦点対象2人が先に弁明し、その他の生存AIが意見を出す。設定時間の60%を上限にする
- `awaiting_master_advice`: 必ず主人へ操作を返し、討論の残り時間を固定する
- `response`: 主人の助言または「相談せず続ける」後、予約した40%以上の残り時間で再開する
- Lab/CLIで人間がいない場合は、明示的な `discussion_advice_skipped` イベントを記録して自動再開する
- 総発言上限からもresponse用を最低1件予約する。openingが時間切れ・上限到達しても裁判へ飛ばさず、必ず主人相談へ移る
- 相談後の期限を過ぎた助言と、時間切れ後に完成したAI発言は採用しない

主人が読む時間を150秒から差し引かないため、考えている間に討論が終わる問題を避ける。150秒は `discussionDurationSec` で変更可能な仮値である。

### 2. 個別AIの質問ラリー

- 各AIの評価・発言を個別に実行し、完了した発言から画面へ反映する
- 明示的な質問は `question → answer → follow_up` を優先する
- 人間が指定した質問を最優先する
- 同一バッチの疑い返しを最大1件に抑え、直近発言者の連投を避ける
- 初日は前日投票が存在しないため「昨日の投票理由」を選択肢から外す
- 質問テーマを外部設定からプロンプトへ渡す

ただし、次バッチへ進む前には現在バッチ内の最も遅いAIを待つ。完全なストリーミング会話ではなく、Phase0の既知制限である。

### 3. 単調さと無根拠な疑いを抑制

- 名前を出された、焦点対象になった、静かだったという理由だけで疑わない
- 回答、同意、保留、撤回を許し、全発言へ疑い先を強制しない
- 侮辱、嘲笑、脅し、初心者や専門用語への圧力を禁止する
- 公開事実にない過去投票や夜の出来事を作らない
- モックの弁明・確定情報への反応テンプレートを増やし、日本語の破綻を修正する

### 4. 情報共有ループを初日から検証

Quick Test / Quick-info / Pack Testは `firstNightDivination: "white"` とし、占い主人へ初日白情報を1件通知する。情報は主人にだけ見え、自動でバディへ漏れない。主人が確定情報共有を選んだ場合だけバディが事実として知る。

Quick Testの裁判親密度補正は `linear / maxBonus: 32` を維持する。これは正解率最大化ではなく、親密度が高いバディほど主人の本気の意見を優先するという企画意図に基づく。親密度MAXでも必ず反転する実装にはせず、極端な評価差では自分の判断を残すテストを維持する。

### 5. Live原価と保存量を抑制

- 公開イベントのうち投票等は保持し、評価プロンプトへ含める発言本文を直近24件へ制限する
- JSON再試行は成功試行だけでなく、Edgeが返せた失敗試行のtokenも合算する。締切Abortやusageを返せない通信障害は依然として推定額へ含められない
- 公開Labの進行中メモリでは生コールを全件保持するが、再読込後は直近30コールだけ復元する
- 完全な生ログが必要な場合は、リロード前に試合JSONを書き出す
- 勝敗確定ステップで `finishedAt` を即時記録し、総試合時間の欠損を直す

モデルを変えると討論構造の効果と混ざるため、候補版も `anthropic/claude-sonnet-5`、effort `low` のまま比較する。プロンプトとQuick系ルールのバージョンは `0.8.0-human-turn.1`。

## 公開Liveの課金保護

Edge Functionで次を強制する。

| 項目 | 既定上限 |
|---|---:|
| HTTP本文 | 192 KiB |
| system / userプロンプト | 24,000 / 48,000文字 |
| 評価 / 発言出力 | 1,200 / 400 tokens |
| reasoning effort | `low` |
| OpenRouter待機 | 90秒 |
| 同一isolate内の同時実行 | 8件 |
| 同一isolate内の30分件数 | 320件 |

`AI_BUDDY_LAB_LIVE_DISABLED=true` で生成だけを緊急停止できる。IP、端末識別子、愛言葉、APIキーは保存しない。Edgeは複数isolateで動くため、30分件数は全体の厳密な課金上限ではない。異常時の最終防衛線はOpenRouter側の利用上限・APIキー停止である。詳細は `supabase/functions/ai-buddy-lab/COST_GUARD.md`。

### 調整後A：狼主人

- 初日5人の冒頭発言後、時計が止まって主人相談へ移った
- 主人がレンへ「現在最も疑っている相手」を質問すると、レンだけが先に回答した
- レンの逆質問を、ミナとセバスが「自分の仮説を出さず話を返した」と同じ公開ログから追及した
- 2日目はヒメとタクが、前日にレンへ仮説開示を求めたミナ自身も見立てを伏せていた矛盾を指摘した
- 主人の「ヒメが怪しい」はミナの評価・発言・投票へ反映され、裁判補正は+16.0。ミナはヒメへ投票した
- ヒメとタクは主人助言に影響されず、公開矛盾を根拠にミナへ投票して狼を処刑した

主人の助言が物語を変えつつ、相手AIの推理で覆される本作の核が成立した。強い追及はあったが、侮辱、初心者排斥、専門用語による圧力、秘密漏えい、架空イベントは観察されなかった。

### 調整後B：占い主人

- 役職ポップアップの直後、初日白情報「レンは狼憑きではない」が主人だけへ別ポップアップで届いた
- 冒頭討論中のミナは白情報を知らず、主人が相談で「確定情報の共有」を選んだ後だけ内部事実として認識した
- 共有後の判断理由に「レンは確定情報で白」と記録され、裁判ではレンの疑いを15に抑え、主人と同じセバスへ投票した
- ミナは白情報を公開せず役職を伏せたため、他3人の票でレンが処刑された。ミナもその夜に襲撃され、狼が勝った
- 脱落後は主人相談を自動スキップし、残ったAIだけで質問・回答・反論を続けて完走した

秘密分離、主人からの確定共有、AI内部への事実登録、投票反映はすべて成立した。一方、共有済み白対象へ3票が集まる状況でも公表しなかったため、占い役プロンプトには「白対象の処刑リスクと役職露出リスクを比較する」という評価軸が不足している可能性がある。強制公開へ即変更すると1試合への過適合になるため、次は同条件を3〜5試合測り、白対象が最多票候補のときだけ公開を強める条件付き案と比較する。

## 現時点の判断

候補版は、旧版で欠落していた「人間が考え、助言し、その結果をAI同士が議論する」という本作の核を、進行ルールとして保証した。公開Liveでも「優しいがぬるくない」「名指しが連続反論へつながる」「主人の1回の相談が物語を変える」の3点を確認でき、旧設定より少ないコールと原価で成立した。したがって `0.8.0-human-turn.1` をPhase0の現行推奨設定として維持する。

次段階は、占い白の条件付き公表を3〜5試合で比較すること、Packの勝率調整、バッチ内最遅AI待ちの解消、長期戦で直近24発言より前の矛盾を要約保持することである。完全なリアルタイム配信やモデル変更は討論構造の効果と混ざるため、この検証と同時には行わない。
