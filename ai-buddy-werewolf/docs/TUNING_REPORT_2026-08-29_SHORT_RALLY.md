# 短文ラリー・攻め筋分散 調整レポート（2026-08-29）

## 目的

9組Live AIで確認された次の問題を、テンポを落とさず改善する。

- セバスなどの長い前置きで会話を追いにくい
- 複数バディが「具体的な根拠がない」「自分の見立てがない」と同じ攻め筋を繰り返す
- 主人の介入が1日1回だけで、議論へ参加した実感が薄い
- 指名質問への回答前後にも重い評価コールが入り、ラリーが遅い
- 誰が誰へ返したのか、モバイル画面で追いにくい

## 旧公開版のLive基準値

公開版 `35bf2dc`、本格9組、`anthropic/claude-sonnet-5` で1日目討論から裁判直前までを実測した。

| 指標 | 旧公開版 |
|---|---:|
| AIコール | 23 |
| 入力token | 113,819 |
| 出力token | 9,235 |
| 推定原価 | $0.3200 |
| 延べAI処理時間 | 197.9秒 |
| エラー / JSON失敗 / フォールバック | 2 / 5 / 2 |

質的には、冒頭9発言がすべて「ミナには自分の見立て・具体的理由・判断材料がない」という同系統へ集中した。セバスは冒頭約250文字、主人質問への回答も約230文字で、挨拶・前置き・全体要約がラリーを止めていた。質問テーマ内部ID `most_suspicious` が公開文へ混ざる例もあった。

## 採用した調整

1. バディごとの観察担当を決定論的に分散
   - 回答回避、二者比較、発言と投票の整合、同意の時機と新規根拠、疑い始めた時機、反対仮説、庇い・距離取り、身内切り、焦点移動を能力値に応じて割り当てる
   - 同じシードでは再現し、別シードでは担当を回転する。結論の一致は禁止せず、同じ理由・役割・言い回しだけを避ける
2. 発言を原則1〜2文へ短縮
   - 人格は一人称・語尾・短い感情だけへ反映し、長い執事の前置きや全員の要約を禁止
   - Live構造化出力とブラウザ検証を最大120文字にし、ゲームコアにも文末優先の安全網を置く
3. 指名質問の高速化
   - `answer` / `follow_up` は、当日かつ主人の新入力より後に作られた討論評価だけを再利用し、通常は発言コール1回で返す
   - 前日評価・裁判/夜評価・助言前評価は再利用しない
4. 主人相談を本格9組で1日2回へ
   - 冒頭後に1回、応答討論が3発言進んだ後に追加1回
   - 質問→回答→受け止めの途中では相談を割り込ませない。見送りも1機会として残数へ反映する
5. モバイル表示
   - 名前を色付き `@名前`、指名回答を「↩ 名前への返答」で表示
   - 相談説明の重複を減らし、シートへ明示的な閉じるボタンとEsc操作を追加
6. 主人相談を会話へ確実に反映
   - 未完了の質問往復を終えた直後、人間バディが主人の最新相談を読んで一度だけ見解を更新する
   - 相談内容や主人の存在は円卓へ明かさず、親密度と自分の推理の両方で判断する
7. 公開ログ接地と重複質問の強化
   - 「互いに庇った」「先に」「後付け」「判断を変えた」などは公開ログで成立するときだけ使う
   - 初日弁明は自分の説明へ限定し、並列生成の表示順を心理戦の根拠にしない
   - その日に回答済みの「相手×質問テーマ」を進行側でも再発行しない
8. Live構造化評価の狭い安全補修
   - score配列の不正が1要素だけなら、その要素だけ除外してLive評価を継続する
   - 2要素以上、配列欠落、confidence等の異常は従来どおり拒否する
   - 候補外・死亡・自分・狼仲間IDをブラウザ側でも除外し、補修数を再試行と分けて記録する

同一条件の最終 `.3` は旧版比で、コール+21.7%、入力+31.4%だが、出力-22.7%、原価+15.8%、延べAI処理-18.6%となった。会話を9発言から16発言へ増やし、主人相談を2回、完全な質問→回答→受け止めを2組成立させても、長文出力と処理時間は減った。

最終 `.3` の16発言は、平均46.4文字、P95/最大62文字、16/16文面ユニーク、120文字超過0、内部ID漏れ0。主人の2回目相談後はミナが最初に見解を更新した。初日意見は、二者同列、同じ逃げ方という疑い、矛盾なし、役職名乗りの確認、疑いすぎへの反論、二者の違い、レン自身への疑問へ分散した。

質的な辛口評価は、旧版6.5/10 → 接地強化途中7.0/10 → 最終 `.3` **7.8/10**。合格条件として置いた「同じ元発言への攻撃は最大2人」「並列表示順の時系列破綻0」「未回答に見える質問と同義再質問0」を同一シードで満たした。別シードでも弁明の自己完結、短文化、反対仮説、主人相談2回の流れは再現した。

別シードでは、途中に別質問を挟むと同じ相手へ同じテーマを再質問する例が1件見つかった。この実測後、当日中の「相手×テーマ」を再発行しない進行ガードと回帰テストを追加した。

有料実測は候補4回 **$1.5193**、旧基準を含む合計 **$1.8393**。許可上限$10を大きく下回った。

### Live構造化評価の観測

同一シード最終試験では、`finish_reason=stop` でも suspicion配列の1参加者だけscoreが欠落し、評価全体がモックへ落ちる例を3件確認した。一方、別シードではフォールバック0・JSON再試行1だったため、モデルの非決定的な構造出力揺れである。

これに対し、score配列だけを対象に「不正1件まで除外、2件以上は拒否」するEdge補修、BuddyContext候補ID制限、競合重複ID除外、補修件数の監査記録を実装した。ローカルのEdgeテスト13/13とWeb単体テストで確認済み。ただし実運用Edgeへはまだデプロイしていないため、公開環境で補修成功になることは未実測である。

## 現時点の判断

最終 `.3` は次期候補として採用可能。短さ、会話量、主人介入、質問ラリー、公開ログ接地、攻め筋の意味分散が旧版より改善し、原価増は約16%に収まった。結論を無理に散らさず、同じ結論なら別の公開根拠を要求するため、確定情報がある局面で人工的な逆張りも起こしにくい。

次の観測項目は「材料不足・保留・急がない」が新しい安全テンプレにならないか。今後調整するなら、保留時に判断を変える条件を1つ添える、過去の異なる立場がログにある場合だけ「判断が変わった」と言う、follow_upはまず回答内容を評価する、の3点に限定する。今回さらに大きく動かすと、改善した接地と分散を崩す可能性がある。

公開反映前の残り作業は、実運用EdgeとPagesのデプロイ、補修記録が公開Labで表示されることの1コール確認、しんちゃん本人の体感プレイである。
