# 意思決定の記録

企画としての確定事項と、Phase0限りの仮決定を混同しないこと。変更する場合はこの文書を先に更新する。

## 1. 企画として確定していること(Phase0でも削らない)

- 人間主人 + AIバディの二人一組。討論・質問・嘘・推理・最終投票を行うのは**AIバディ**
- 主人の助言は**命令ではなく判断材料**。AIは信頼度に応じて重み付けし、最終判断は自分で行う
- 役職スキルの結果(占い等)は**まず主人だけに届く**。主人が共有した場合のみAIが事実として知る
- 討論中の主人の介入は**原則1日1回・選択式**(自由文章入力なし)
- 裁判で主人は一人を選ぶが、それは**意思表示**であり直接の一票ではない。最終投票はAI。主人とAIの選択が異なることを許容し、両者を表示する
- 裁判時には新しい確定情報を共有できない
- 夜襲も同構造: 狼主人は提案、狼AIが評価、複数狼は統合して決定。結果後に提案/第一候補/最終対象を狼主人へ表示
- **内部スコア(怪しい度・襲撃優先度・仮説等)は試合中に公開しない**。試合後のリプレイ/分析でのみ確認可能
- 確定情報は信頼度補正の対象外(事実として扱う)。ただし使い方(公開/温存)はAIが決める
- 人格(名前・口調・キャラ性)は表現にのみ影響し、推論力・虚言力・信頼度と分離する
- 3能力は「10ポイントごとに新観点/新技術をアンロック + 中間ポイントで精度向上」という構造。虚言力が高くても必ず騙せるわけではない
- 信頼度MAXでも100%服従しない
- ゲーム内でAIバディを「AI」と呼ばない(相棒・バディとして扱う)

## 2. Phase0だけの仮決定(いつでも変更してよい / 変更手段)

| 項目 | 仮決定 | 変更手段 |
|---|---|---|
| プリセット | Quick Test(5組/狼1/占1/3日)・Pack Test(8組/狼2/占1/4日) | `config/presets/` |
| 討論 | 1日1周・各1発言・席順固定 | プリセット |
| 助言 | 1日1回、メニュー5種、質問テーマ5種、立ち回り4種 | プリセット + `config/advice.json` |
| 信頼度補正 | 線形加算(trial/night 25、skill 30、主観助言 20) | プリセット `trust.*` |
| 襲撃統合 | 各狼の補正後優先度を正規化して合算、同点シード付きランダム | プリセット |
| 同票処理 | 候補からシード付きランダム | プリセット(方式追加はコード) |
| 最大日数到達 | 引き分け | `checkWin`/engine(コード) |
| 死亡時の役職公開 | しない | プリセット `revealRoleOnDeath` |
| 占い | 各夜1回・初日フリー占いなし・結果は翌朝主人へ・同一対象の再占いは候補が尽きた時のみ | engine(コード) |
| 投票の公開 | 誰が誰に投票したかは公開情報 | engine(コード) |
| 裁判の意思表示 | 主人選択はAIプロンプトに入れず、エンジンが数値補正として適用(二重計上防止) | engine(コード) |
| 主人の意思表示の棄権 | ポリシー主人はnull可・人間主人は選択必須(UI上) | UI/engine |
| モックの能力表現 | 実装済みidのみ分岐(それ以外はLiveプロンプト専用) | `mock.ts` |
| 既定モデル | `claude-opus-5`(effort: low) | `config/models.json` |
| Live評価の構造化出力 | Record回避のため配列で受けて変換 | `anthropic.ts` |

## 3. まだ未決定のこと

- 助言メニューの最終ラインナップと影響度の適正値(検証で決める)
- 討論の適正周回数・発言長(所要時間と面白さのトレードオフ)
- 占い役のCO(役職公開)をどの程度AIの自由にするか
- 引き分けの扱い(最大日数の適正値、引き分けを廃止すべきか)
- 信頼度の増減システム(Phase0は固定値。育成・変動は本番構想)
- 先行生成の具体設計(評価の先読み深さ、助言による無効化の扱い)
- 本番のマルチプレイ構成(Phase0はローカル単一プレイヤー)

## 4. 技術上の仮定

- ローカル単一ユーザー・単一プロセスで十分(認証・スケールアウトなし)
- 永続化はJSONファイルで十分(SQLiteは不要と判断。移行するなら`MatchRecord`スキーマをそのままテーブル化)
- クライアントはポーリング(2.5秒)で十分。リアルタイム性が必要になったらSSE/WebSocketへ
- LLM呼び出しはサーバー側のみ(APIキー保護)。この境界は本番でも維持
- プロバイダーはAnthropicのみ実装(抽象化済みのため追加は小さい)
- Node 20+ / TypeScript strict / ESM。tsx実行(サーバーのビルド成果物は作らない)
- モックの決定論はシード+ラベル導出乱数で担保(呼び出し順非依存)

## 5. 今後、実測して判断すること

- 1試合の総時間・AI待機時間が体験として許容範囲か(モデル/effort/トークン上限の調整)
- 1試合あたりのAPI原価(モデル別)と、討論品質とのバランス
- 主人の選択とAI投票の一致率の適正帯(高すぎ=服従、低すぎ=無視)
- 信頼度補正 maxBonus の適正値(評価スコア分布に対して逆転が起きる頻度)
- 狼AIの嘘が市民AIに看破される率(虚言力・推論力の値付け)
- 質問指定→回答の会話が成立する率(プロンプト改善の主戦場)
- JSON構造化出力の失敗率・リトライ率(スキーマの複雑さ調整)
