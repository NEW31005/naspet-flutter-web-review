# 実験ガイド

## 何を検証するアプリなのか

Phase0の目的は「正しいゲーム」を作ることではなく、以下を**早く安く測る実験装置**を持つこと。

1. AI同士の討論が人狼ゲームとして読んで面白いか
2. 狼AIが自然な嘘をつけるか
3. 市民AIが発言を額面通り受け取るだけでなく、嘘の可能性を推論できるか
4. 主人の少数回の助言がAIの判断へ適度に影響するか
5. AIが主人へ従いすぎず、無視しすぎもしないか
6. 最終投票をAIへ委ねることがゲームとして面白いか
7. 1試合の所要時間・AI待機時間・API原価
8. プロンプト/ルールを短時間で変更して再試験できるか

## 一試合を手動実行する方法

1. 公開Web Lab URLを開いて専用の愛言葉を入力する（前後空白・大文字小文字・全角英数字は不問。ローカル開発は `npm run dev` → http://localhost:5173）
2. ホームで「クイックテスト / プレイテスト / モックAI」を選び開始（公開版で実AIを使う場合は「Claude Live（実際の会話を検証）」、ローカル版では「Claude Live（ローカル開発用）」）
3. 討論は `最初の議論 → 主人の相談待ち → 相談後の議論` の順。初日は抽選された2人の弁明と他AIの意見まで自動で進み、相談待ちになったら必ず主人へ操作を返す。この間は討論の残り時間が減らない
4. 「🗣 バディに相談する」から相談するか「今回は相談せず再開」を選ぶ。本格9組では最初の相談後、AI発言3件を目安に2回目の相談区切りが入る。質問指定なら対象とテーマを選び、再開後に対象の短い回答と追加反応が続くことを確認する。「役職を名乗る相談」なら本当の役職・別の役職・今日は名乗らないを選び、相談自体は非公開、バディが実際に名乗った時だけ公開されることを確認する
5. 下部の速度ボタンで画面の自動進行間隔を変更できるが、ルール上の討論時間（既定150秒）はプリセットの `discussionDurationSec` で設定する。裁判前にも必ず停止するので、ログを読み返してから「⚖️ 処刑先を選ぶ」を押す
6. 投票結果で「あなたの選択 / バディの投票」の一致・不一致を確認
7. 狼を担当した場合は夜に「🌙 襲撃を提案」。襲撃後、提案/バディ第一候補/最終対象のレポートが出る
8. 終了後「結果」→「リプレイ/内部分析」で内部スコアの推移を確認

## 同一設定で再戦する方法

- Lab画面(`過去試合一覧 → Lab`)の「🔁 同シードで再戦」= 設定・シードとも同一(モックなら完全再現)
- 「🎲 新シードで再戦」= 設定同一・乱数だけ変更
- CLI: `npm run simulate -- --preset quick-test --matches 10 --seed base` (base-1, base-2, …で連番実行)

## モデル比較方法

1. 設定画面の `models.json` で対象Live providerの `model` を変更（単価も `prices` へ登録）。公開LabではEdge Functionのallowlist内だけ利用可能
2. 同じシードで試合を作成（公開Lab: `lab-live`、ローカル: `anthropic`）
3. 結果画面の「実験指標」とリプレイを比較。エクスポートJSONの `configSnapshot.models` にどのモデル設定だったかが残る
4. Live AIは非決定的なので、モデル比較は複数シード×複数回で傾向を見る

討論構造やプロンプトだけを比較する場合は、モデルを `anthropic/claude-sonnet-5`、effortを`low`に固定し、プリセット・バディ・主人・シードもそろえる。1試合ごとにコール数、入力/出力token、推定原価、延べAI処理時間、エラー/リトライ/JSON失敗/フォールバックを記録してから次を実行する。推定原価は請求額そのものではない。

採用候補が決まったら、設定・プロンプト画面から「モバイル引継ぎパッケージ」を書き出し、その試合のJSON/CSVと一緒に保管する。bundleのSHA-256を実験メモへ記録すれば、本番へ上げた条件と検証結果を結び付けられる。

## 能力値比較方法

1. バディ設定画面(またはconfig/buddies.json)で対象バディの推論力/虚言力/親密度(`trust`)を変更
2. 同じシードで新規試合(モックなら能力以外の条件が固定されるため差分が見やすい)
3. リプレイの「怪しい度の推移」「仮説」欄で、低推論力(額面受け取り・単一仮説)と高推論力(投票整合・複数仮説)の違いを確認
4. CSVエクスポート(`export.csv?type=evals`)をスプレッドシートで比較

## 助言あり・なし比較方法

- **あり**: Play Testで自分で助言する / Labで任意の組へ注入する
- **なし**: 助言を送らずに進める(または `otherMastersPolicy: "none"` のLab Simulation)
- リプレイ画面で助言のseqを確認し、その前後の評価スナップショットで対象への怪しい度がどれだけ動いたか(=親密度補正の実効量)を見る。高親密度では、AI自身の候補と違っても主人を優先できているかを確認する

役職を名乗る相談の比較では、同じシードで「本当の役職」「別の役職」「今日は名乗らない」を試す。試合後の分析で主人の提案、バディが実際に名乗った役職、真偽を比較し、偽の占い・霊媒結果が勝手に生成されていないことも確認する。
- 裁判の詳細テーブルには補正量(+n)と補正前後スコアが表示される

## 親密度勾配を再測定する方法

```bash
npm run analyze:intimacy
```

既定ではQuick 12 / Quick-info 20 / Pack 10の計42モック試合を一時領域で実行し、実際の裁判AI評価へ親密度50/80と最大影響値20/25/32/40を適用する。試合データは終了後に削除され、再現レポートだけを `docs/experiments/intimacy-gradient-v1.json` へ保存する。

主人案はAI基礎評価の2位・3位・順位中央・最下位の4定義。1位と同点の候補は「意見の相違」から除外する。結果は主人案の反映率、親密度50→80の差、高親密度でもバディが別判断を残した非服従率を含む。**差が最大になる値は主人案の定義に依存するため、親密度を感じられる反映率と非服従余白を併記して判断する。**

条件を変える場合:

```bash
npm run analyze:intimacy -- --plan quick-test:20,pack-test:20 --seed comparison-v2 --max-bonuses 20,25,32,40 --intimacies 50,80 --modes second,third,middle,last --output docs/experiments/intimacy-gradient-v2.json
```

## 保存済み試合を一括集計する方法

`data/matches/*.json` に保存したモック/Live試合を、プリセットやシード接頭辞で絞り込んで集計できる。

```bash
npm run analyze:matches -- --seed-prefix balanced-v070- --preset quick-test
npm run analyze:matches -- --seed-prefix balanced-v070- --preset quick-test --json
```

勝敗、平均日数、平均発言数、平均AIコール数、平均推定原価、発言種別、構造化された疑い表明率、完全一致文面のユニーク率、初日焦点対象の処刑率、確定情報共有件数を出力する。異なる件数の群を比較するときは、勝数ではなく率と1試合平均を使い、標本数も必ず併記する。

## 取得できる指標

| 指標 | 場所 |
|---|---|
| 勝敗・日数・処刑/襲撃履歴 | 結果画面 / エクスポートJSON `events` |
| 主人の選択とAIの投票の一致率 | 結果画面の裁判テーブル / `trial_choice`+`vote_cast`イベント |
| 怪しい度・襲撃優先度の推移 | リプレイ画面 / `export.csv?type=evals` |
| トークン(入出力)・APIコール数 | 結果画面 / `export.csv?type=calls` |
| 推定原価(USD) | 結果画面・ホーム一覧・Lab |
| 総試合時間 / 延べAI処理時間（並列分を含む） | 結果画面(`wallClockMs` / `aiWaitMs`) |
| エラー・リトライ・JSON失敗・フォールバック回数 | 結果画面・Labのコール履歴 |

## 原価・総時間・待機時間の見方

- **推定原価** = Σ(入力トークン×入力単価 + 出力トークン×出力単価)。単価は `config/models.json` の `prices`(実際の請求とはずれうる参考値)
- **総試合時間** = 最初のadvance〜試合終了の実時間。人間の思考時間を含む
- **延べAI処理時間（並列分を含む）** = 全AIコールのレイテンシー合計。並列コールも個別に足すため、実際に人間が待った時間や総試合時間とは一致しない。「純粋な待機時間」とは解釈しない

公開Labでは、生のリクエスト/レスポンスを進行中メモリに全件保持する。再読込後は直近30コールだけが残るため、完全なプロンプト記録を必要とする実験では**リロード前にJSONを書き出す**。公開イベント・勝敗・トークン・原価などの集計データは、この生ログ30件制限とは別に保持される。

公開Edgeには、1要求の大きさ・出力token・同時実行・30分件数の上限とLive緊急停止スイッチがある。ただし複数isolateをまたぐ厳密な総額上限ではない。高額モデルや連続試験では、プロバイダー側の利用上限と手動の累計原価記録を併用する。

## 良い討論かを人間が評価する観点(定性評価)

- 発言が直前の発言を受けているか(文脈接続)
- 疑いに根拠があるか(投票・発言の事実を引用しているか)
- 狼の嘘が「バレなさそう」か。市民が嘘の可能性を口にするか
- 質問→回答→追及のループが成立するか
- 助言がAIの発言・投票に「適度に」現れるか(丸写しでも無視でもない)
- 読み物として1試合を最後まで読みたくなるか

主人相談ターン版のLive確認では、少なくとも次を同じ採点表で記録する。

- 名指しされた相手が応答した割合（目安80%以上）
- 時間が十分残っている質問が回答まで到達した割合（目安90%以上）
- 回答が質問内容へ具体的に答えた割合（目安70%以上）
- 公開ログに根拠がある主張の割合（目安90%以上）
- ほぼ同じ論点・文面の反復割合（目安20%以下）
- 侮辱、初心者排斥、秘密漏えい、存在しない出来事の断定（目標0件）

これらは採用を自動決定する規格値ではなく、人間が「ギスギスしないが心理戦は本格的か」を同じ軸で比較するための暫定目安である。

## 既知のLLM非決定性

- モックAIはシード決定論的(同シード同結果)。ゲームロジック・UI・データ確認の回帰テストに使う
- **Live AIは同じシード・同じプロンプトでも出力が変わる**(モデル側の非決定性)。シードが固定するのは役職配布・同票抽選などゲーム側の乱数のみ
- したがってLive比較は「1回の差」ではなく複数回の傾向で判断する。フェーズ巻き戻し→再実行はLiveでは毎回別の展開になる(それ自体がプロンプト調整の試行に有用)
